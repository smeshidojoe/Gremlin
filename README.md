# Gremlin — модераторский бот для Telegram

Бот-модератор на aiogram 3. Добавляется в любой чат, настраивается владельцем через личное меню, у владельца бота — отдельная админ-панель.

## Возможности

- **Инлайн-боты** — Telegram не позволяет запретить сам вызов инлайн-бота на клиенте, поэтому сообщение с `via_bot` мгновенно удаляется, юзер получает настраиваемое наказание (удаление / мут с выбором времени / бан).
- **Ссылки** — два независимых тумблера: *телеграм-ссылки* (`t.me` / `telegram.me` / `tg://` на сторонние чаты, каналы и истории; вкл по умолчанию) и *внешние ссылки* (любые сайты; выкл по умолчанию). Ссылки на сам чат и упоминания людей не трогаются. Наказание общее, настраивается. Опционально: проверка `@упоминаний` каналов, блок пересылок из каналов.
- **Системные сообщения** — отдельные тумблеры на уведомления о входе, о выходе и на прочие служебные (закреп, смена названия/фото).
- **Защита от чужих чатов** — бот работает только там, куда его добавил владелец или человек из списка доступа. В любом другом чате он выходит сам и присылает владельцу уведомление.
- **Сообщения от имени групп/каналов** — удаление + бан отправителя-канала. Анонимные админы чата и привязанный канал не трогаются. Вайтлист разрешённых отправителей.
- **Стоп-слова** — `слово` (точное) или `слово*` (с любыми окончаниями), наказание настраивается.
- **Антифлуд** (опционально) — N сообщений за M секунд → мут.
- **Варны** (опционально) — `!warn причина`, при достижении лимита — наказание, счётчик сбрасывается.
- **Капча новичкам** (опционально, по умолчанию выключена) — новый участник получает мут и кнопку «Я не бот»; не нажал за отведённое время → кик.
- **Приветствие новичков** (опционально) — настраиваемый текст с `{name}`, прошлое приветствие удаляется (анти-спам).
- **Жалобы** — `!report` / `!репорт` ответом на сообщение: карточка в лог-чат со ссылкой, автором, комментарием и **копией медиа**, если оно было. По умолчанию доступно всем; тумблером «только из списка» круг жалобщиков ограничивается (по id/username, админы чата могут всегда).
- **Поддержка** — кнопка в меню бота: юзер шлёт тикет (текст/фото/видео/гиф/войс) → уходит разработчику в личку или в заданный чат тикетов (настраивается в админ-панели).
- **Медиа-фильтры** (опционально) — удаление выбранных типов: стикеры, гифки, голосовые, кружки, фото, видео, файлы, музыка. Без наказания.
- **Триггеры** (опционально) — ключевая фраза внутри сообщения → авто-ответ текстом или медиа, до 20 на чат, кулдаун 30 сек.
- **Счётчики** (опционально) — свои развлекательные команды со счётом: `!черви` → бот отвечает реплаем `кузнечики [1]`, где число это счётчик вызовов в этом чате (растёт с каждым ответом, переживает перезапуск). Скобки со счётчиком дописываются автоматически. У каждого счётчика свой кулдаун — пока он идёт, бот молчит и вызов не засчитывается. Имена системных команд занять нельзя, до 30 счётчиков на чат.
- **Статистика чата** — страница в меню: сообщения за день/неделю/всего, топ-5 за неделю, пришло/ушло за 7 дней, наказания.
- **Наблюдение за профилями** (опционально, по умолчанию выключено) — скоринг профилей и сообщений: невидимые символы, обфускация (гомоглифы, руны, символы-заменители), telegra.ph-ссылки, рекламные/CJK-имена, упоминания ботов. Выше порога «подозрение» — карточка в лог-чат с кнопками «Заблокировать / Не трогать»; выше порога «бан» — автобан. Пороги настраиваются селекторами. Изменение профиля участника → повторная проверка и новая карточка. Ботов, добавленных не-админом, банит сразу (отключаемо). «Не трогать» не снимает наблюдение — юзер продолжает проверяться остальными правилами.
- **Вайтлист юзеров** — по id или @username, с уровнем игнора (всё / только инлайн / только ссылки / стоп-слова / антифлуд).
- **Команды в чате** (админы чата, ответом на сообщение): `!mute [5m|1h|2d] [причина]`, `!ban [причина]`, `!warn [причина]`, `!unmute`, `!unban`, `!unwarn` (работают и русские алиасы `!мут`, `!бан`, `!варн`...).
- **Карточки событий** — в отдельный лог-чат летит карточка: кто, что, причина, кнопки «Разблокировать / Так ему и надо» (для мута — «Размутить»). При разбане бот шлёт юзеру инвайт-ссылку в личку. Ручные баны/муты админами чата тоже дают карточки. Какие типы событий слать — настраивается.
- **Чистка сервисных сообщений** — вход/выход из чата (опционально).
- Каждая функция включается/выключается отдельно. **Вся настройка — в одном меню бота, без слэш-команд.** Меню живёт в одном сообщении (редактирование), селекторы — кнопки `◀ значение ▶`. Лог-чат и привязка чужого чата тоже выбираются кнопками в меню.

## Команды

| Где | Команда | Что |
|---|---|---|
| личка | `/start`, `/menu` | единое меню — всё настраивается тут |

Меню одно для всех: владелец бота видит в нём дополнительные кнопки (статистика, рассылка, лог, доступ к боту). Первая кнопка — **💬 Чаты**: список чатов, где работает бот (владелец бота видит все, обычный юзер — свои). Клик по чату открывает мини-дашборд: данные чата, сводка настроек, разделы, выбор лог-чата, наказания, статистика.

**Доступ к боту** — последняя кнопка меню у владельца: список допущенных по id/@username. Пока список пуст, бот открыт всем; как только добавлена первая запись — доступ только по списку.

Лог-чат выбирается в разделе «Карточки и лог» через нативный выбор чата Telegram (кнопка открывает системный список чатов, где есть бот). Привязать чат, где вы уже админ (бота добавил кто-то другой), — кнопка «Привязать чат» в главном меню. Глобальный лог событий и чат тикетов (для владельца бота) — в админ-панели.

Команды бота в чате доступны всем, у кого есть админ-права в этом чате.

## Админ-панель

Статистика (юзеры/чаты/наказания/события), состояние, список всех чатов (лог, настройки любого чата, смена владельца, выход из чата), поиск юзера, бан доступа к боту, рассылка, лог ошибок, экспорт CSV, глобальный лог событий.

## Запуск в Docker

```bash
docker compose up -d --build
```

Всё изменяемое живёт в `./data` на хосте и монтируется в контейнер: база бота, база статистики, сессия юзербота, медиа триггеров, лог. `.env` тоже читается прямо из папки проекта (только на чтение) — правка токенов не требует пересборки, достаточно `docker compose restart`.

Память ограничена 4 ГБ (`mem_limit`), swap отключён — при утечке контейнер упадёт и перезапустится, а не начнёт свопиться. Логи ротируются (3 файла по 10 МБ). `tini` пробрасывает сигналы, поэтому `docker compose stop` завершает бота штатно: закрывается база и отключается юзербот.

**Перед первым запуском** перенеси существующую базу в `data/`, иначе бот стартует с пустой:

```bash
mv gremlin.sqlite3 data/
```

Полезное:

```bash
docker compose logs -f
```

## Запуск без Docker

```bash
pip install -r requirements.txt
cp .env.example .env   # вписать BOT_TOKEN
python -m gremlin
```

У @BotFather боту нужно **выключить** privacy mode (`/setprivacy` → Disable), иначе бот не видит обычные сообщения в группах. В чате боту нужны права: удаление сообщений, блокировка пользователей, приглашение по ссылке.

При старте бот сбрасывает накопленные за простой апдейты (`drop_pending_updates`) и не действует на сообщения старше 2 минут — чтобы после перезапуска не дублировать баны, которые админы уже выдали вручную. Ctrl+C завершает бота без трейсбека.

## Mini App (необязательно)

Настройки чата можно открывать не только в меню бота, но и в Telegram Mini App — той же функциональностью. Оба интерфейса читают **один** источник — [`schema.py`](gremlin/schema.py) (декларативное описание разделов и полей). Добавил/изменил настройку там (+ колонку в `db.Settings`/схеме) — подхватят и меню бота, и аппка. Дублировать правки не нужно.

- Бэкенд: [`web.py`](gremlin/web.py) (aiohttp) — API поверх тех же `db.py`/`schema.py`. Авторизация — валидация Telegram `initData` (HMAC по токену бота).
- Фронт: [`webapp/index.html`](gremlin/webapp/index.html) — рендерит форму из `/api/settings`, тема берётся из Telegram.

Включение: задать `WEBAPP_URL` (публичный **HTTPS**-адрес) в `.env`. Тогда бот поднимет веб-сервер и покажет кнопку «🖥 Открыть в приложении» в меню. Пусто — аппка выключена, всё работает через меню. Для Telegram обязателен HTTPS (за реверс-прокси с сертификатом).

## Хранение

Одна SQLite-база `gremlin.sqlite3` (WAL): чаты, настройки по чату, вайтлисты, стоп-слова, варны, наказания, события, юзеры бота. Данные каждого юзера (его чаты через `chats.owner_id`) и все настройки его чатов лежат тут же; админ управляет ими через те же функции с любым `chat_id`.
